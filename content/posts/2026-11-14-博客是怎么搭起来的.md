整站只有一个 Python 脚本、一套 CSS、一堆 Markdown。（11-17 重写：原来那版写的是"打算怎么做"，这版写的是"做完了，数字在这儿"。这篇同时演示写法：标题、粗体、行内代码、引用、列表、表格、代码块都用上了。）

## 这套东西现在多大

| 部分 | 实测 | 说明 |
| --- | --- | --- |
| `build.py` | 515 行 | 唯一的生成器，只用 Python 标准库 |
| `assets/endfield.css` | 2,232 行 | 外观全部来自开源的 `hhikr/endfield-ui-skill`（MIT，不含任何游戏素材） |
| `assets/site.css` | 112 行 | 只管排布，不定义颜色 |
| `assets/fx.js` | 268 行 | 数字滚动、主题切换；语法卡在 ES2017 |
| 生成一次 | **0.07–0.08 秒**（量了三次） | 页面少，脚本就没理由慢 |
| 提交到线上 | Actions **23–29 秒**（六次实测） | 跑完再等 8 秒 curl 拿到的就已经是新内容 |
| `dist/` | 8.6 MB | 大头是字体 `Saira.ttf` 476 KB，样式才 64 KB |

## 为什么坚持零依赖

CI 那一头只保证有 Python。构建脚本 `python3 build.py` 不需要装任何东西，也就不存在"这台能跑那台不能跑"。要装东西的只有改图和改样式时才跑的工具：`favicon.py`（要 Pillow）、`sharecard.py` 和 `wdshot.py`（要 geckodriver）、`check-es.py`（要走网络拿 acorn）。它们都不参与构建。

## 页面上的数字都是现算的

篇数、字数、阅读分钟、每个分类的字数、"第 N 天"，全部是 `build.py` 从 `content/` 现算出来的。字数算法是汉字按字计、拉丁按词计，文章页、列表页、分类账、总数用的是同一个函数——**这套风格不允许界面上手写统计数字**，改了内容它们自己会变。

> 引用左边一条竖线，文字退成次要颜色。适合放结论。

## 修过的三个 bug，每个都有数

1. **字体晚到，整行在抖。** 数字滚动时随机字形宽度不一，右边正文被推着走，实测 **29.8px** 抖动。加字体 preload + 按位数把宽度钉死（`ch`）+ 滚动前锁宽，降到 **0.05px**，九帧里右列正文一帧都没挪。
2. **鼠标一进那一栏，正文被整段拽走。** 开场滚动的计时器没留住 handle，hover 又放了一遍动画，`cancelAnimationFrame` 留下的状态是"在跑但没有占位宽度"，那一栏先乱缩 **34px**、正文被推 **26.3px**。改成 hover 先掐计时器再滚，之后宽度全程锁死。
3. **CI 上的"今天"少一天。** GitHub 的 runner 在 UTC，`date.today()` 让北京时间早上发布的站点日期和第 N 天少一天（线上真的显示过 11.16 / 第 15 天）。改成按作者时区取今天。

## 门禁长什么样

```bash
python3 build.py     # 生成 dist/
python3 check-es.py  # 5 处 JS 按 ES2017 / ES2015 / ES5 卡上限，防老内核整份报错
python3 wdshot.py "http://127.0.0.1:8093/404.html" 404.png 1200 900   # 要证据就截真图
```

`check-es.py` 这个门禁是被现实逼出来的：主题按钮点不动，最后查出来是老内核解析不了 `?.`，整块模块在解析阶段就报错——而 CSS 和地址参数全都照常，看着就像"只有按钮坏了"。
